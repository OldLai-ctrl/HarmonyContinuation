# Phase 1 和声模型

## 输入与边界

Cubase 的 VST-XML 由 `src/plugin/` 解析成 `ChordEvent[]`，导入成功后才在界面线程调用 `analyzeHarmony`。`src/core/` 不引用 VST3、VSTGUI 或 Windows 头文件。播放头更新仅调用既有和弦定位逻辑，不重算和声。核心也可用 `HC_BUILD_PLUGIN=OFF` 在没有 SDK 的环境独立构建。

## 和弦标准化

内部音高类以 C=0 至 B=11 表示。原始名称中的升降号拼写另存为 `rootSpelling`，避免把 C# 与 Db 的显示信息提前抹掉。根音优先取 `ChordEvent.root` 或 `keyNoteValue mod 12`；名称辅助验证。低音优先取结构字段，缺失时暂以根音作为默认低音。Cubase 实测中 `mask` 有两种表现：Cmaj7 的 `0x891` 可直接表示根音、三音、五音、七音；C 大三和弦的 `0x48` 与 `pitches=C;E;G;` 相对应，不能直接按同一位序解释。现在先按 `pitches` 得出相对根音的音程集合，并用 `mask` 交叉验证；当 `mask` 符合实测的省略根音、位序偏移形式时也接受。无法解释的冲突会保留诊断并降低置信度。名称与结构冲突时仍以可识别的结构为准。

基础性质支持大小三和弦、属七、大七、小七、减三、减七、半减七、增三、sus2、sus4。6、9、maj9、m9、7b9、7#9、13 先作为颜色音或七和弦身份保留；复杂扩展及换位拼写还未做完整理论解释。

## 调性候选

默认给 12 个大调和 12 个小调评分并排序。小调同时允许自然小调材料与常见和声小调属和弦，不再单独宣称检测出某种小调音阶。评分使用调内和弦相容性、主和弦证据、V→I/i、ii→V→I、持续时间的有限相对权重，以及已解决的次属、次导音、平行小调借用解释。权重集中在 `HarmonyAnalysisWeights`。候选 `confidence` 是当前规则下 24 个候选的归一化相对分数，不能当作经过统计校准的真实概率。

`AnalysisContext.forcedKey` 可覆盖自动首选调性，候选列表仍保留给用户参考。短而未终止的最后一颗 OPEN 和弦不被当作句末终止证据。

## 级数、功能与角色

`ScaleDegree` 保存 1–7 级及半音升降；罗马数字由独立格式化函数生成。功能类别是 Unknown、Tonic、TonicProlongation、Predominant、Dominant、ChromaticPredominant、ChromaticDominant。角色使用可组合位标志，因此次属、转位、趋近及结构地位互不排斥。

在选定调性下，若属三或属七和弦按纯五度关系解决到调内非主级，标记 `SecondaryDominant` 并保存目标级；若减三或减七和弦从目标根音下方半音解决，标记 `SecondaryLeadingTone`。大调支持 iv、bIII、bVI、bVII 借用。短时值且直接解决的次属或次导音可另标 `Approach`，不会把所有短和弦称为经过和弦。无法可靠解释时功能保留 Unknown。

## 结构权重与两个输出

每颗和弦的 `structuralWeight` 位于 0–1。第一版使用相对持续时间、明确功能、终止参与、段落端点、已知拍号下的小节起点、短时值趋近及目标解决。OPEN 不会因为缺少时长而被置零。次属角色不决定结构地位：短 A7→Dm 可以省略，整小节 A7→Dm 可以保留。`FULL` 保留全部事件；`SKELETON` 保留端点、终止链及达到阈值的事件，结果以原事件索引表示，不复制或改写导入事件。

## 当前边界

- 调性置信度未经真实语料校准；相对大小有意义，百分比不宜解释为客观正确率。
- `C→E7→Am` 自动优先 A 小调（E7 为 V7）；强制 C 大调时可分析成 V7/vi。这是有意保留的歧义。
- 借用判定限大调的 iv、bIII、bVI、bVII；旋律小调、变和弦、远关系转调与完整换位拼写尚未覆盖。
- `Passing`、`Substitution` 角色仅预留数据结构，当前不自动判定。重复和弦、复杂节拍重音与声部进行尚未参与结构权重。
- 骨架的阈值和规则是开发版；对异常和声仍需人工审阅，不能作为数据库匹配的最终标签。
- 当前导入会话只存在于插件实例内；Cubase 工程再次加载后的自动恢复尚未实现。
