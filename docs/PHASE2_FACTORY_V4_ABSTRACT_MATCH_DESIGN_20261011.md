## 结论摘要

1. 本阶段没有修改正式推荐行为，也没有修改 Factory、数据库结构、用户库、快照、安装器、正式标签或 main。离线对照只扩展了现有 RecommendationReliabilityTests 测试中的诊断输出，没有另写独立工具。
2. R01 的模拟输入识别无误。5 条 Factory 路径均通过匹配、续写、实现和路径检查，最后都因固定的 8 分未解释插入惩罚而低于 60 分门槛。它们不是“没有相似路径”，但是否音乐上合适仍需人工盲评。
3. R02 的四组 A 小调模拟均无 Color。Color 在可续写候选生成之前被淘汰：COMMON_MINOR_015 对上了三和弦前缀，但 Factory 路径已到末尾；另三个小调 Color 对齐低于 0.60。强制 C 大调后，84 个 Color 条目有返回对齐，其中 14 个有尾部，但相似度最高只有 0.581427，仍全部在最低匹配门槛处退出。
4. 当前 657 条 Factory 全部进入匹配；候选损失不是短名单截断。当前 DP 对每个模板只保留一个最佳窗口，可能丢掉“分数稍低但有尾部”的替代窗口。这个结构可作为后续验证方向，尚未证明它是 R02 的根因。
5. 建议先用真实 Cubase 成功/失败输入和人工盲评标签建立基线，再做独立的、可关闭的分级兼容与续写窗口实验。不能仅放宽全局 60 分或 0.60 匹配门槛。

本报告区分已测事实、设计建议和待验证事项；它不是 Phase 3 实施授权。

### 2.1 当前抽象表示的具体边界

- src/core/MusicTypes.h:7-10 的 ChordQuality 没有独立的 9、11、13 和弦性质类型。
- src/core/HarmonyAnalysis.h:34-50 保存根音、低音、和弦性质、音程/颜色掩码等字段；src/core/ChordPitchSet.cpp:3-17 将归一化结果转换为音高集合。
- src/core/ChordNormalizer.cpp:32-68, 99-139, 142-253 将多个和弦扩展折入有限的核心性质和颜色字段。当前可把 maj9 归为 Major7 核心并保留九音颜色；11/#11 的解析覆盖不完整，需先用输入测试补齐语义表。
- src/core/ProgressionMatcher.cpp:37-43 已有少量扩展兼容：Major/Major7、Minor/Minor7、Major/Dominant7、Diminished/Diminished7 等。将 Major 与 Dominant7 同样按低代价处理会弱化大小七度性质差异，是应在离线评估中重点检查的风险。
- src/core/ProgressionMatcher.cpp:103-164 对调式级数、性质、功能、角色、目标、显式低音及音程掩码计价。显式音集合不一致可额外产生代价；目前没有一张清晰、可直接审阅的“核心和弦性质兼容等级表”。
- 当前同一模板仅保留一个最佳窗口。如果最佳对齐落在模板最后，系统不一定保留该模板中另一个有尾部、但匹配分略低的窗口。是否需要多个续写窗口，应通过本报告提出的离线实验确定。

## 3. R01：五条候选的评分审计

### 3.1 输入与匹配窗口

模拟条件：A 小调，4/4，120 BPM，每和弦 4 QN；输入为 Am → G#dim → G → D/F#。对照只将最后和弦改为 D。

| 输入和弦 | MIDI 低音 | MIDI 上方音 | QN | 实际识别结果 |
|---|---:|---|---:|---|
| Am | 45 | 69、72、76 | 0–4 | A 小三和弦，低音 A |
| G#dim | 44 | 68、71、74 | 4–8 | Abdim，减三和弦，低音音级 8 |
| G | 43 | 67、71、74 | 8–12 | G 大三和弦 |
| D/F# | 42 | 62、66、69 | 12–16 | D/Gb，大三和弦，低音音级 6 |
| D 对照 | 38 | 62、66、69 | 12–16 | D 大三和弦，低音 D |

识别使用音高等价类，所以 G#dim 被拼写为 Abdim，F# 低音被拼写为 Gb。两者根音音级、性质和低音音级均正确。D/F# 与 D 两次模拟获得相同候选、分数及阶段数，故本案例没有证据显示转位额外限制了 Factory 匹配。

两次完整查询阶段数相同：shortlist 657 → aligned 184 → similarity 5 → tail 5 → realization 5 → path 5 → distinct 5 → scorePassed 0 → output 0。短前缀 Am → G#dim 和局部片段 G#dim → G → D/F# 各有 184 个对齐尝试，但没有一个达到 0.60。代码支持连续片段匹配，不代表这两个特定片段有足够分数。

## 5. 抽象和弦兼容关系设计

### 5.1 建议分层

兼容等级作用于和弦身份比较，不把不同性质压成同一个身份。方向性表示“输入信息不足时可尝试更具体模板”，并不表示两者完全等价。

| 关系 | 建议等级 | 正例 | 负例与限制 |
|---|---|---|---|
| 同根音、同核心性质、等音拼写 | Tier 1：等价 | G# 与 Ab；同为小三和弦 | 不因拼写差异增加惩罚；根音音级不同不能归为等价 |
| 转位、八度、音域、配器不同 | 默认不约束主身份 | C/E 与 C；同和弦不同八度或配器 | 若输入和 Factory 都显式标注功能低音，才作为单独的次级比较；不能默认要求同低音 |
| 省略五度 | Tier 2：信息不足兼容 | C、E 两音可候选匹配 C 大三和弦 | 只剩根音或没有可辨三度时不能强认大/小；增减五度不能当普通省略 |
| 同三和弦核心上增加扩展音 | Tier 2：方向性兼容 | C → Cmaj7 → Cmaj9；根音与大三度保留，附加七/九音有单独代价 | 不能将 C、Cmaj7、Cmaj9 视为完全相同；C 的缺少七/九音不是相反证据 |
| C 大三和弦与属七和弦 | Tier 2/3 条件关系 | C 输入在明确属功能环境中可检索 C7 路线 | 默认不按 Major7 等价处理；C7 的小七度是核心定义，需较大代价或语境要求 |
| 大三与小三 | 硬负例 | C 对 Cm | 三度相反会改变核心和弦性质，不得仅凭同根音合并 |
| 大七与属七 | 硬负例或高代价 Tier 3 | Cmaj7 对 C7 | 大七度与小七度性质必须保留；不得沿用当前对 Major/Major7 与 Major/Dominant7 的同等低扩展代价 |
| sus2 / sus4 | 独立核心；有限 Tier 3 | Csus2 对 Csus4 可作为同根音色彩近邻 | 不等价于 C 或 Cm；如果查询缺少三度，优先保持不确定 |
| 减三和弦、半减七、全减七 | 各自独立；有限 Tier 3 | Cdim 对 Cdim7 可有共享结构关系 | dim、ø7、dim7 不等价；增强和弦也不能并入大三和弦 |
| 9、11、13 扩展 | 核心与扩展拆开 | Cmaj9 保留 Major 核心并单记 9；G13 保留属七核心并单记 13 | 缺失的 11/#11 解析不能静默丢弃；Cmaj9 与 C9 的大/小七度仍不同 |
| 非和弦低音 | 默认不作为核心冲突 | C/B 可按 C 核心比较 | Factory 显式低音是编配语义；若输入低音明确且冲突，应记录软冲突或按意图单独过滤，不应影响普通和弦默认召回 |
| 借用和弦 / 调性变化 | 保留根音、性质及变音级数；调性作为证据 | A 小调中的大 IV 与其 Dorian/借用语境可保持不同角色 | 不把 bII 和 II、bVI 和 VI 视为同一身份；不能由“当前调性不一致”单独证明和弦不可能 |

### 5.2 C → Cmaj7/Cmaj9 的推荐处理

C 大三和弦应能以有限代价检索到部分 Cmaj7 或 Cmaj9 Factory 路径，但命中应标注为“核心相合、模板增加扩展音”，不应变成 Tier 1 完全命中。三度缺失时，输入核心性质置信度下降；缺少七度或九度则是未观测，不能当作冲突。相反，C 与 Cm、Cmaj7 与 C7、C 与结构性 sus/减和弦必须保留差别。

## 6. 召回优化候选方案

### 方案 A：最小、可控的适配评分与后备通道

1. 保留当前 Tier 1 路径及 60 分常规显示门槛。
2. 仅对有明确结构证据的单个查询插入项，评估其能否被归类为已解释连接音；不能仅因相似度接近门槛而消除 −8 分。R01 的 G#dim 插入项是重点离线正例，但尚无人工质量标签，不能在本阶段改罚分。
3. 对通过 Tier 1 匹配、具有非空 Factory 尾部、且没有硬性质冲突的候选，允许进入独立的 Tier 2 影子名单；先只记录来源 ID、完整 Factory 路径、兼容理由和分项分数，不改变 UI。
4. Color 不因 intent 偏好而强行加分，也不延长已经结束且不可循环的路径。

**召回收益：** 可检验 R01 的插入解释是否值得减少罚分；保留近似候选及退出理由供评审。
**误配风险：** chromatic 插入规则可能把不相关和弦当作装饰连接；候选需要盲评。
**性能：** 在已返回的 MatchResult 上增加少量标记与重排，预期成本较低；需要实测，当前无毫秒基线。
**回归风险：** 中低，但修改全局插入代价仍可能影响非 R01 输入。影子名单隔离风险最低。
**不能解决的情况：** 没有 Factory 尾部的 COMMON_MINOR_015；也不能仅靠插入罚分让 C 大调 Color 近似命中跨过 0.60。

### 方案 B：分级兼容与保留多个有尾部窗口

候选设计为三层，顺序与分组可在评估后调整：

- 第一层：高置信度同根音/等音、同核心性质匹配；默认忽略转位、八度、音域和配器。
- 第二层：有证据的扩展和弦、缺五度、低音差异等方向性兼容；保留核心性质差异与解释标签。
- 第三层：受控连续片段/结构相似，允许合理插入或替代；需至少足够的独立和弦证据、Factory 原路径尾部和明确的误差原因。不得跨越硬性质冲突。

对每条 Factory 路径保留有限个“匹配窗口 + 非空续写尾部”备选，而非只取一个最高相似窗口。每个推荐必须仍指向一个真实 Factory ID 和 Factory 原始完整路径；不能生成新的即时和弦路径。较低层只能填补空位，不能挤掉高层结果；层内再使用现有意图、节奏、质量分排序。

**召回收益：** 能检验短上下文、不同长度前缀、中间片段和扩展兼容是否找到真实 Factory 尾部。
**误配风险：** 局部结构相似更容易跨越功能或性质不同的进行；需硬负例和配额。
**性能：** Factory 657 条当前全部扫描。每格兼容计算较轻；保留多个窗口会增加每模板候选量和排序/内存，成本随保留窗口数增长，必须在现有 657 条数据库和规模测试上量测。没有当前延迟基线，不能承诺毫秒数。
**回归风险：** 中高；涉及核心匹配、过滤和候选排序，必须影子运行、A/B 离线比较、可关闭并逐步启用。
**不能解决的情况：** Factory 本身没有尾部、路径不可循环或真实语境与剩余模板均冲突时，应诚实返回无 Color，而非伪造续写。

### 方案对比

| 维度 | 方案 A | 方案 B |
|---|---|---|
| 目标 | 解释现有近失候选，先隔离风险 | 扩展候选窗口与兼容关系 |
| 首选落点 | 插入项分类、影子候选记录 | 匹配比较器、对齐结果集、分层排序 |
| 预期收益 | 低到中；针对已识别的评分损失 | 中到高；可覆盖扩展和替代窗口 |
| 错误候选风险 | 较低，尤其只影子记录时 | 较高，需人工标签和层级限制 |
| 性能成本 | 低，仍待实测 | 中，n-best 对齐须限额并压测 |
| 推荐顺序 | 先做 | 只有 A 与评估集通过后再做 |

## 7. Factory 可检索性与 Color 限制

### 7.1 现有能力

- Factory 657 条低于索引上限 800，当前不是索引短名单遗漏。
- 当前模板级 DP 能匹配不同起点以及局部连续片段，也能对查询插入、模板跳过和和弦替代计费。
- Factory 使用相对调式级数，可以在不同主音中复用；但当前模板大/小调模式严格过滤。
- 现状是每模板返回一个最佳对齐，因此“支持局部片段”并不等于“保留所有可能续写的窗口”。
- 节奏用于候选评分而非选择 DP 路径；OPEN 会影响可用时值和建议时值，不是独立的 Color 生成条件。
- ColorPreferenceReranker 只重排已经存在的项；preferredIntent=Color 不是 Color 召回开关。
- Factory Color 总计 89 条，其中 85 条大调、4 条小调。按原始序列长度统计，88 条至少有 4 个和弦，另 1 条为 3 和弦循环路径。这只是路径长度上限信息，不代表某一输入一定能匹配到其尾部。
- 针对本次 F–G–Am：A 小调仅 0/4 个返回的 Color 最佳对齐同时拥有可用尾部；C 大调是 14/84 个已返回 Color 对齐有尾部，但 84 个都未达到最低相似度。因此，当前 Color 短缺同时包含模式、最佳窗口、最低匹配门槛和具体路径内容；不能简化成单一显示或排序问题。

### 7.2 多长度前缀和局部窗口

建议离线索引单位不是“Factory 模板命中数”，而是“输入窗口 → 模板窗口 → 可用尾部”。每条记录应能给出：Factory ID、窗口起止、匹配输入数、兼容层、硬冲突、尾部长度、是否循环、意图及最后过滤原因。

短前缀可降低缺失早期音符的影响，却增加偶然命中；中间连续片段可绕过前缀不相似，但必须防止把中间片段的语义错当作整句意图。尾部耗尽必须是明确的不可续写状态，不能用相似性掩盖。

移调复用已有相对级数逻辑，不应复制 Factory 记录。调性候选可作为有限解释假设；跨大小调不宜无条件合并，需将模式一致性作为语境证据并保留借用和弦差异。

## 8. 离线评估集与验收标准

### 8.1 数据集组成

以已存在的 Factory 数据与输入形式做受控变体，不把同一模板的派生变体拆到训练与验收两侧。至少包括：

- R01 完整输入、D/F# 与 D 对照、Am–G#dim 短前缀和 G#dim–G–D/F# 连续局部片段。
- R02 四组 T1–T4、A 小调语境和 C 大调语境；实际 Cubase 成功/失败输入收到后并入独立锁定集。
- dev.3 B08、B11 原有合成案例，含转位与省略五度的正例及错误低音/核心性质负例。
- 仅改转位/斜杠低音、仅省略五度、C/Cmaj7/Cmaj9 扩展、C/Cm 与 Cmaj7/C7 硬负例、sus/减/半减/全减对照。
- 同一和弦序列改变主音、大小调语境、节奏、OPEN；FULL 与 SKELETON。
- Color、Resolve、Develop、Loop 各意图。确保既有同调式，也有合理借用和弦正例。

每个用例应锁定：HarmonyAnalysis 输入、Factory 快照哈希、调性语境、配器/模式、Intent、OPEN、权重和门槛。每条候选保存 Factory ID、原始路径、命中窗口、所有分项、过滤及展示结果。

### 8.2 指标和基线

现有可核实的候选链基线仅包括模拟结果：

| R02 A 小调 T1–T4 | 每组 5 条 Resolve/Loop 输出，Color 0 |

### 8.3 建议的量化放行门槛

以下是 Phase 3 评估的提案，不是当前已达成的结果：

1. Tier 1 在锁定精确回归集上的召回保持 100%（基线是现有已通过精确/等价案例）；任何已通过正例丢失即阻止合并。
2. 已标注硬负例中，Tier 1 误判数为 0；根音/三度性质冲突不得作为完全等价命中。
3. 每条显示结果的 Factory ID、原始路径和尾部来源追溯率为 100%；数据库内容不得因检索而改变。
4. 在盲标集上同时报告 Recall@5、Precision@5、MRR 和按意图拆分结果；相对当前同一数据、同一设置基线，目标是 Recall@5 增加且 Precision@5 不下降。由于真实 R01/R02 候选还没有人类标签，当前无法给出其数值，也不应虚构。
5. R01/R02 的目标用例必须至少各有一条被盲标为“可用”或“特定语境可用”的候选进入前 5，才算该用例的召回改善；若没有合理 Factory 路径，正确结果可以是无候选并归类为曲库覆盖缺口。
6. 每组、每层、每意图分别报告误匹配数和排序退化数；低层结果把高层已接受候选挤出前 5 的次数必须为 0。
7. 性能需先实测当前 657 条基线，再实测新方案 p50/p95 和峰值候选量。只有在产品端预先批准性能预算后才能判断通过；Phase 2 没有性能基线，故不编造毫秒阈值。

## 9. R02 真实 Cubase 证据采集方案

当前不能宣称已定位真实 R02。最小采集以此前成功与失败的两次输入为一对，优先复用插件已有的单实例本地输入/推荐诊断导出，不引入常驻大日志：

1. 插件 Build ID、Cubase 版本，以及成功/失败实例各自的导出文件。
2. 原始音符 MIDI 音高号、起止 tick 或 QN、力度、轨道和通道；若输入为和弦轨道，再附宿主和弦符号 XML。
3. 插件解析后的逐和弦根音、核心性质、低音、扩展音、起止位置、OPEN 标记。
4. 实际调性状态：AUTO 或强制值；FULL/SKELETON、输入模式、Intent、Color 偏好、其他过滤项及候选数量设置。
5. 诊断中的每层数量、每个 Color 候选 ID、命中窗口、尾部、分项分数和淘汰原因。
6. UI 默认区与 More 区候选 ID/顺序，或现有 ACTUAL_UI 诊断片段，以判定是否为显示差异。
7. 成功与失败两组之间每次只比较一个设置；若原始素材允许，先核对同一 MIDI 与同一调性，再核对 OPEN、节奏和 FULL/SKELETON。

这些数据足以将问题分到识别、模式解释、召回、匹配门槛、尾部/续写、评分、意图/过滤、去重或显示。若本地导出当前未记录候选 ID 与逐项过滤原因，最小诊断增量应仅在显式导出时添加这两个字段；不需要持久化会话日志或更改推荐结果。

## 10. 建议的分阶段实施顺序

1. **先补真实基线**：收集成功与失败 Cubase 导出；冻结当前 Factory 哈希、配置和完整结果。
2. **完成盲标**：审阅 R01 五条完整路径、Color 近似路线及硬负例；没有通过的候选不能靠改分数变成“正确”。
3. **影子实验 A**：现有结果旁计算兼容解释与插入分类，不改变正常输出；评估候选排名、质量和 p50/p95。
4. **影子实验 B**：在已有 DP 上保留有限个有尾部窗口，和单最佳窗口对照；量化新增可接受候选与硬负例。
5. **审查并单独批准核心改动**：先改兼容比较器，再改多窗口选择，分开提交以便归因。
6. **小范围集成**：只有离线门槛通过后才连接推荐输出；以独立开关禁用新增层，逐步扩大覆盖。
7. **回归与回退**：运行相关匹配、续写、MIDI、Cubase 合成用例；按 Factory 哈希验证内容不变。若质量或性能回退，关闭新增层或回退独立提交即可，不需迁移数据库。
