# Phase 3.5 session state

`PluginSessionState` is the single editor-session model. It stores the imported chord progression, coordinate mode and revision, Auto/Forced key, selected style and intent, FULL/SKELETON view, active tab, debug preference, at most three pinned candidate IDs, meter, and factory library version. Imported chord data retain their project QN values and names, quality, note values, optional roots/bass, duration/OPEN state, and the raw chord fields needed for analysis. Thus a Cubase project can restore the same project anchor. Saved User Library templates use relative phrase time instead.

`src/session/PluginSessionState.*` provides a bounded, versioned `HCS3` binary serializer independent of Cubase. Version 3 adds logical `editorWidth` and `editorHeight`; older `HCS1` and `HCS2` states migrate with the 1100 × 900 default. Unknown versions remain unsupported. It rejects malformed/truncated data, invalid enum values, too many chords or pins, non-finite times, invalid sizes, and oversized strings. Unit tests cover the round trip, migration, corrupt data, and library-version mismatch. Changing only the editor size, view, tab, pin, or debug preference does not request analysis. Style or intent requests a ranking run that reuses the last analysis/query when the phrase revision matches. Key, progression, or meter changes request analysis and recommendation.

The VST3 controller implements `getState` and `setState` using the serializer. The processor's existing `HC00` state remains its audio-side state. Session restore reloads the current factory/user libraries and recomputes analysis, matching, and recommendations. It does not serialize the RecommendationSet, worker state, debug logs, or playback cursor. A changed factory library version does not reject the session; it is recomputed with the installed library. Pin IDs are retained; a missing source path is shown as unavailable until it can be resolved.

Controller state persistence is **IMPLEMENTED; MANUAL CUBASE HOST TEST REQUIRED**. The SDK Validator verifies VST3 contract behavior, but it cannot prove that Cubase saves, closes, and reopens these editor fields in a project.
