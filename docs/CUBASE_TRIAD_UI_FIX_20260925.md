# 2026-09-25 真实三和弦与界面刷新修复

## 用户实测

Cubase 15 中拖入 `C → G → G#dim → Am → Em` 成功。截图中的 `mask` 依次为 `0x48`、`0x48`、`0x24`、`0x44`、`0x44`，同时有可读的 `pitches`。旧版将这些 mask 直接当成含根音的音程集合，五颗和弦性质因此识别为 Unknown；顶部候选仅约 8%，无法提供有用的调性判断。用户还观察到播放头经过后块内文字消失，以及底部黄条与边框不对齐。

## 修复

- 和弦标准化同时读取结构化 `pitches` 与 `mask`。对于实测的三和弦格式，`0x48` 与 C–E–G 的相对音程集合 `0x091` 相符；`0x44`、`0x24` 同理。若两者无法互相解释，优先采用可识别的音符列表，保留冲突诊断并降低置信度。七和弦原有的 `0x891` 等格式继续兼容。
- 播放引起局部重绘时，绘制函数显式设置字体，并重绘播放头所在的整个和弦块，避免只刷新一条窄区域后留下无字块。
- 权重黄条改为绘制在块边框内侧，左右与底部都留出间距，不再覆盖边框。
- 顶部明确显示自动首选调性；候选接近时加“有歧义”，百分数标为候选权重，不暗示客观正确率。

## 可重复验证

新增 `tests/fixtures/harmony/cubase_triads_mask.json`，内容按用户截图的五颗和弦、QN、音符和 mask 重建。开发命令行输出：C Major 0.22、E Minor 0.18、G Major 0.18；FULL 为 `I → V → vii°/vi → vi → iii`，G#dim 标记次导音与趋近，SKELETON 为 `I → V → vi → iii`。这组和弦本身仍有调性歧义，首选 C 大调不等于唯一正确答案。

黄金测试逐颗检查大三、小三、减三和弦性质、归一化音程集合、次导音角色和候选调性。UI 的实际观感需要在 Cubase 中对修复版再次确认，自动测试无法模拟宿主绘制过程。

## 黄条二次修订（用户再次实测后）

用户发来的第二张 Cubase 截图确认：C Major（有歧义）已经显示，五个和弦块的文字在播放后仍可见。黄条仍让用户感觉与块边框不齐。该截图里各黄条底边在同一高度，但终点不同；原因是原实现把“结构权重”映射为黄条的长度，短条与块的右边界不齐，并非截图能证明的跨屏 DPI 错位。

现在让黄条铺满每个块的左右内边，用粗细表示结构权重。读取 VSTGUI 绘制上下文的实际缩放比，再把黄条四边对齐到物理像素，避免 125%、150% 等非整数缩放下产生半像素边缘；徽标文字与黄条留出间距。`WeightBarGeometryTests` 检查 100%、125%、150%、200% 缩放下的宽度、底边、粗细和像素对齐。几何测试不能代替 Cubase 对最终画面的确认。

## 黄条样式恢复与播放线残影（用户第三次实测后）
