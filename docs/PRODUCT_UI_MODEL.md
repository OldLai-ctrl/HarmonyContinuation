# Phase 3.5 product UI model

The editor defaults to 1100 × 900 logical pixels and supports independent width and height resizing. Compact uses two top rows and one recommendation column; Standard uses two columns; Wide uses two or four columns according to card width. Details are in [RESPONSIVE_UI.md](RESPONSIVE_UI.md). The top controls contain Key, Style, Intent, View, RECOMMEND, and LIBRARY. Key defaults to Auto and displays the leading interpretation; forcing one of 24 major/minor keys reruns analysis, matching, and recommendation. Style is a ranking signal, never a template filter. Intent changes ranking and lane order without discarding the other three groups. FULL/SKELETON changes only the visible current chord blocks. A transport update redraws only the current timeline lane.

CURRENT PHRASE keeps duration-scaled chord blocks, the verified length-based yellow structural-weight indicator, a dashed OPEN edge, and a moving playhead. Clicking a chord shows its degree, function, weight, roles, target, analysis confidence, duration, and start QN. The normal block view displays only name, degree/function, and one high-priority role badge.

RECOMMEND shows Resolve, Develop, Loop, and Color lanes. Each normally displays three candidates, or `No strong option`. A candidate's timeline shows muted existing chords, a bright suggested suffix, and a visible boundary. Its current OPEN block uses that candidate's proposed total hold duration. The number beside a path is an ordinal ranking score, with no percent sign. `Show More` exposes retained candidates (the worker asks for up to ten per lane). Clicking a card opens a compact inspector with score components, source templates, continuation fingerprint, and alignment operations. Clicking Pin puts at most three paths in the comparison tray; pins remain available while changing tabs or ranking choices. Pin does not write a library entry.

Save opens an inline form for name, style, intent, and optional comma-separated tags. The chosen existing context and continuation become a relative-time, key-independent user template in `user.db`. LIBRARY loads factory and user metadata once on entry/after an edit; it offers style, intent, mode, and name/tag search. Factory entries are read only. User entries support name/metadata changes and confirmed deletion. The QA inspector shows ID, FULL, skeleton, rhythm, style, intent, cadence, prior, tags, and a warning count for matching skeleton/rhythm fingerprints. It does not edit factory seeds.

Empty state: `Drag Chords From Cubase`. Work in progress: `Analyzing…`. A lane without a strong option: `No strong option`. Library load failure and invalid input have separate brief status labels; detailed diagnostics live on MATCH / DEBUG. No audio, MIDI, drag-back, chord-track mutation, networking, telemetry, or recommendation weight tuning is part of this phase.

The presentation policy is in `src/session/ProductServices.*`: minimum score 60, no relative-to-best restriction, three visible per lane, and no extra presentation-level diversity filtering. All four values are configurable. The engine's original match/score thresholds and diversity behavior remain intact.
