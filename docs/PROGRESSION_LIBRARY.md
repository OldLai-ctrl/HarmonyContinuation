# Progression Library, Phase 3

The factory catalogue is maintained as eight JSON files in `data/factory/`. Each row is one key independent harmonic phrase. `tools/generate_seed_json.py` contains the explicit seed list used to write the first 161 rows; it does not transpose or combine rows. The JSON files are the reviewed source. They include 141 major and 20 minor phrases. Style membership overlaps: Pop 101, Jazz 80, Functional 61, Rock 60, R&B 40, City Pop 20. Primary intents: Resolve 59, Color 42, Develop 36, Loop 24. This is a small initial seed catalogue, not a claim of complete musical coverage.

`data/schema/progression.schema.json` documents the source fields. `db_compiler` checks the required factory fields, range/enum values, chord notation, positive finite durations, phrase length, unique IDs, and exact musical/metadata duplicates. Similar skeletons are reported, since style, intent, or rhythm variants may be intentional. `prepareTemplate` computes the skeleton and fingerprint. The compiler writes and reads back `factory.db`; plugin loading reads this database once in its worker, then matching uses memory. The JSON parser and compiler reject an invalid source build.

Each entry uses the Phase 2 `ProgressionTemplate` type. The sequence is relative Roman notation, with complete relative quarter note durations. Supported style IDs are `pop`, `rock`, `rnb`, `jazz`, `citypop`, and `functional`; `style:weight` values range from 0 to 1 and styles are soft ranking hints. Intent is one of Neutral, Develop, Resolve, Loop, or Color. Cadence is a separate, stable field. `priorWeight` is an editorial familiarity weight, not a measured frequency or probability. One entry ends at one phrase boundary. Loop entries may wrap once during recommendation.

Both SQLite databases have `schema_version=1`, `library_version=1`, and `library_type`. Unknown versions or wrong database types are rejected. `factory.db` is shipped in the VST3 bundle at `Contents/Resources/factory.db` and opened read only. `user.db` is separate, under `%LOCALAPPDATA%/HarmonyContinuation/user.db` for the plugin. A factory rebuild never touches the user file. Phase 3 implements a version check; future changes need an explicit user database migration before opening an older version for edits.

`UserLibrary` provides add, update, remove, list, and load APIs. The development command `recommend_cli save progression.json --key C:major --name "My phrase" --id USER_my_phrase` saves one custom phrase to the same user directory the plugin reads by default. It subtracts the first project QN before analysis and stores only key independent degrees and relative durations, so a Cubase project position is not retained. An OPEN final chord is closed at a provisional 4 QN when saved. The API keeps factory and user templates in the same in memory index. Reopen the plugin to reload CLI edits into a running plugin instance. `--user path/to/user.db` overrides the directory for testing.

On Windows this build links the SQLite library supplied by Windows; it does not fetch a dependency at build time. Other platforms require a local SQLite3 development package.
