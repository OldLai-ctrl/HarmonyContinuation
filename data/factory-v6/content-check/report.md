# v6 候选内容独立核验

日期：2026-10-24。只读检查 `content/candidates.json`、`content/metadata.json` 与源仓库的和弦实现；确定性核验脚本见同目录 `audit.py`。没有修改候选、算法或库，也没有进行人工听审。

## 结果

60 条候选与 60 条元数据按 ID 完全对齐。逐条比较实际和弦根音、低音、根音相对音程掩码、时值与节奏描述，发现 **0 处音符/低音不匹配，0 处时值/节奏不匹配**。004 的 3+3+2 QN 与其跨两个 4/4 小节的说明相符。没有需要改谱的具体条目。

候选顶层 `mode` 当前分布为 23 条 `minor`、37 条 `major`，核验脚本据此分别用 C 自然小调或 C 大调坐标解释 `typedData.degree`。这是根音坐标选择，不等同于 Aeolian 或 Ionian 归属；调式家族和 membership 单独记录在元数据中。源实现按 key 的 Major/Minor 音阶把 degree 映射为根音，再把 `intervalMask | colorMask` 写成精确扩展音集，`bassInterval` 独立确定低音（`ContinuationEngine.cpp:183-230`）。按新坐标解码后，60 条根音、低音及和弦音集仍全部与原记谱一致。音程掩码以根音为参照（`HarmonyAnalysis.h:48-49`）；当事件带精确掩码时，预览配器不会把声部裁成四音，低音另行发声（`ChordPitchSet.cpp:12`、`ChordVoicer.cpp:37`、`PreviewSynth.cpp:65-66`）。这足以确认掩码语义，但源代码检查没有追到 v6 JSON 文件进入 `ProgressionTemplate` 的产品加载链路，因此不把它表述为已在产品内试听或验证 JSON 预览。

严格音阶集合比较有 22 条额外音级。19 条 `ionian` 元数据行都把借用和声、变化属和/或半音连接写入依据，并把严格音集测试与宽口径归属分开；未发现把这些行误写成严格 Ionian 的证据。其余三条也已标明例外：038 把 Cm9 的 Bb 明确记为借用；052 指出尾部 Cm11 的 D 自然音并拒绝严格 Phrygian；057 的 Ab/Bb 音集本身不能证明旋律上行/下行方向，仍须旋律线确认。没有 Membership 的行标为 uncertain / no global membership asserted，未见强行归属。

未检出完全重复，也没有“仅节奏不同”的同和声重复。需要作为亲缘设计审阅、但不是纯变体的关系如下：

- 016/052 共用 C 低音与 Phrygian 降二框架；Bbm/C 的踏板路线与 Abmaj7/C 的混合色彩路线、尾部 D 自然音不同。
- 021/025 共用 C–B–Bb–A–Ab–G 半音低音家族；021 以 C/G 开放，025 延展至 Cmaj9/G 后再以 Cmaj9 收束。
- 036/038 根音轮廓相同，但前者是静态爵士旋律小调的 CmMaj9–Dm7–G7，后者含 Cm9 的 Bb 借用及 Dm7b5/G7b9 的和声小调色彩。
- 004/009 共用 C 踏板及 Bb/C、F/C，但调式依据、后段和弦与节奏长度不同；014/051 都以 C 踏板显露 Lydian 的 F#，但和弦路线与长时值用途不同；031/054 都采用 C 踏板轮廓，前者有三度和扩展音，后者以无三度挂留和弦避免确定大小调。它们是共享骨架或用途近亲，不是同谱。
